# Архитектура системы распознавания документов

## Структура модуля

Модуль `kyc_document` организован следующим образом:

```
kyc_document/
├── document_processing/          # Основной модуль обработки документов
│   ├── config/                   # Конфигурационные файлы
│   │   └── models_path.yaml      # Пути к моделям
│   ├── models/                   # Хранилище моделей машинного обучения
│   │   ├── Angles90/             # Модель определения угла поворота
│   │   ├── Borders/              # Модель детекции границ документа
│   │   ├── DocType/              # Модель классификации типа документа
│   │   ├── TextFields/           # Модели детекции полей текста
│   │   │   ├── belarus/         # Модели для белорусских документов
│   │   │   └── russia/          # Модели для российских документов
│   │   ├── OCR/                  # Модели OCR (русский и английский)
│   │   ├── Words/                # Модель детекции слов
│   │   ├── PassportPageType/     # Модель определения типа страницы паспорта
│   │   ├── PassportSeal/        # Модель детекции печатей
│   │   └── Quality/              # Модели проверки качества (Blur, Glare, Spoofing)
│   ├── pipeline/                 # Основной пайплайн обработки
│   │   └── pipeline.py           # Главный класс Pipeline
│   ├── pipeline_modules/         # Модули обработки
│   │   ├── base_module.py        # Базовый класс для всех модулей
│   │   ├── angles_classificator/ # Определение угла поворота
│   │   ├── doc_detector/         # Детекция границ документа
│   │   ├── doctype_classificator/# Классификация типа документа
│   │   ├── textfields_detector/  # Детекция полей текста
│   │   │   ├── belarus/          # Для белорусских документов
│   │   │   └── russia/           # Для российских документов
│   │   ├── words_detector/       # Детекция отдельных слов
│   │   ├── ocr_rus/              # OCR для русского текста
│   │   ├── ocr_engnums/          # OCR для английского текста и цифр
│   │   ├── passport_page_type/   # Определение типа страницы паспорта
│   │   ├── passport_seal_detector/# Детекция печатей
│   │   └── Quality modules/      # Модули проверки качества
│   └── processing/               # Утилиты обработки
│       ├── inference.py         # Инференс моделей
│       ├── models.py             # Загрузка моделей
│       ├── preprocessing.py      # Предобработка
│       └── postprocessing.py     # Постобработка
└── scripts/                      # Вспомогательные скрипты
    ├── process_img.py            # Обработка одного изображения
    └── ...
```

## Алгоритм работы пайплайна

Пайплайн обработки документа выполняется последовательно в следующем порядке:

### 1. Подготовка изображения
На старте конвейера входное изображение загружается из файла либо напрямую из массива `numpy`, после чего приводится к формату RGB и нормализуется. Далее применяется масштабирование с сохранением пропорций: длинная сторона ограничивается порогом 1500 px, что обеспечивает баланс между скоростью последующих моделей и сохранением деталей. На этом этапе также фиксируются исходные метаданные (размер, DPI, цветовой профиль), чтобы при необходимости восстановить координаты полей в оригинальной системе отсчёта.

### 2. Определение угла поворота (Angle90)
Определение угла поворота документа выполняется модулем Angle90, который использует компактную классификационную сеть, обученную на четырёх дискретных классах: 0°, 90°, 180° и 270°. Модуль принимает подготовленное изображение, дополнительно нормализует его параметры (кроп, масштаб, mean/std), прогоняет через модель и получает распределение вероятностей по углам. Выбирается наиболее вероятный класс, а если уверенность недостаточно высока, допускается fallback к углу 0°. При отличии от нуля изображение поворачивается средствами OpenCV против часовой стрелки, чтобы вся дальнейшая обработка велась с корректной ориентацией.

### 3. Детекция границ документа (DocDetector)
Модуль DocDetector реализован на базе сегментационной версии YOLO и обучен распознавать внешние контуры паспорта. После получения маски контур переводится в многоугольник, аппроксимируется до четырёх точек и сортируется по часовой стрелке. Используя эти точки, вычисляется матрица перспективного преобразования, которая выпрямляет документ и устраняет геометрические искажения. Результатом шага становится изображение с корректной перспективой и точные координаты углов, которые сохраняются для последующих модулей.

### 4. Классификация типа документа (DocType)
На исправленном изображении запускается модуль DocType, представляющий собой CNN-классификатор, различающий страны и подтипы документов (например, `russia_passport`, `belarus_passport`). На выходе модель возвращает метку и confidence; если уверенность ниже установленного порога, пайплайн завершает работу с признаком `NONE`. При успешной классификации выбираются профили OCR и детекции (набор моделей, словари постобработки, доп. параметры), специфичные для найденного типа документа.

### 5. Определение типа страницы паспорта (PassportPageType)
После классификации документа запускается модуль PassportPageType, который определяет конкретный тип страницы (главный разворот, регистрационная страница, визовая вкладка и т.д.) на основе визуального расположения блоков, печатей и декоративных элементов. Сформированная метка определяет ветку дальнейшей обработки: OCR для разворотов с данными, детекция печатей для регистрационных страниц, специализированные процедуры для визовых штампов. Архитектура модуля изначально расширяема — для каждого многостраничного документа обучается собственная модель классификации страниц, которая подключается к общей точке интеграции без изменения остальных стадий пайплайна.

### 6. Проверка качества изображения (опционально)
Качество оценивается набором специализированных моделей, каждая из которых решает свою задачу: Glare вылавливает блики и засветы, Blur определяет степень размытия, PrintSpoofing и LCDSpoofing проверяют признаки печатной или экранной подделки. Метрики агрегируются в общий отчёт; если включён строгий режим (`low_quality=False`) и хотя бы один показатель не проходит порог, пайплайн завершает работу с соответствующим кодом ошибки, чтобы не тратить ресурсы на заведомо плохой снимок.

### 7. Обработка в зависимости от типа страницы

После классификации страницы пайплайн ветвится на специализированные сценарии, привязанные к типу документа и назначению страницы. Для регистрационных или штамповых страниц активируется детектор печатей (PassportSealDetector), построенный на сегментационной YOLO: он находит все штампы, ранжирует их по свежести/позиции, формирует bounding box, маску и confidence, а затем возвращает структурированную информацию downstream-модулям. Для разворотов с персональными данными срабатывает цепочка TextFieldsDetector → WordsDetector → OCR: сначала специализированная модель детектирует поля, после чего из каждого поля вырезается patch, при необходимости выполняется локальная нормализация и разбиение на отдельные слова. Далее соответствующие OCR-модели (под конкретный язык/алфавит) распознают текст, применяется постобработка, и данные складываются в итоговый словарь. Архитектура допускает добавление новых веток: для каждого документа можно подключить свои детекторы, OCR и постпроцессинг, а одностраничные сценарии могут пропускать ненужные модули, используя только общий интерфейс событий «тип страницы → цепочка обработки».

### 8. Распознавание текста (OCR)
Когда текстовые поля локализованы, запускается OCR-подсистема. Для каждого вырезанного patch подбирается язык (русский или англо-цифровой), после чего изображение нормализуется: приводится к фиксированной высоте, бинаризуется при необходимости и передаётся в последовательную модель (CRNN/Transformer). Результатом является строка с набором вероятностей по символам. Постпроцессинг включает:
- удаление низкоуверенных символов и исправление опечаток по словарям конкретного документа;
- проверку формата (ФИО, серия/номер, даты) с помощью регулярных шаблонов и модулей валидации;
- выравнивание координат в исходном изображении и сохранение confidence для каждого поля.
Распознанные значения агрегируются в структуру `DocumentFields`, где хранятся текст, координаты и метаданные, что упрощает дальнейшую интеграцию в бизнес-процессы.

## Используемые модели по модулям

- **Angle90** — EfficientNet-B3, 4 класса поворота.
- **DocDetector** — сегментационный YOLO с единственным классом `border`.
- **DocType** — MobileNetV3-Small, классы соответствуют пары `country+doc`.
- **PassportPageType** — MobileNetV3-Small, классы страниц задаются для каждого документа.
- **PassportSealDetector** — YOLOv8n-seg, класс `seal`.
- **TextFieldsDetector** — YOLO11n/YOLOv8 детекторы с собственным набором полей на документ.
